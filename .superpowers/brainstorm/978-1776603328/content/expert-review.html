Expert Panel Review

Fully-free stack: Vercel + Supabase + Gemini + BYOK — reviewed by six senior perspectives

⚠️ Critical Issue Found — All Six Perspectives Agree
Supabase pauses your database after 7 days of inactivity on the free tier. If your brother doesn't open the app for a week, the database goes cold and the app returns errors until you manually unpause it from the Supabase dashboard. For a non-technical phone user who might go on holiday, this is a silent killer. This must be addressed before proceeding.
👔 CTO — Decades of Experience

Verdict: Directionally correct, one unacceptable risk, one vendor concern.

The free-first instinct is right for a side project — don't pay until you have to. But the Supabase pause is not a minor inconvenience, it's a reliability SLA of zero. A financial app that silently breaks for a week is worse than one that costs £5/month and works.

Fix: Swap Supabase PostgreSQL for Neon — free PostgreSQL (no pausing, 0.5GB, auto-scales to zero between requests without going offline). Keep Supabase just for auth if you want, or use Clerk's free tier. Cost remains £0.

Vendor lock-in concern: You're now coupled to Vercel's serverless model, Supabase's auth, and Google's Gemini. Each has a free tier today. Have an exit plan: standard PostgreSQL means any provider works; JWT-based auth is portable; the AI abstraction layer you're building already de-risks Gemini dependency.

Missing: No mention of error monitoring (Sentry free tier), no logging strategy, no backup plan for the database. Add these — they're free and will save you hours when something breaks.

⚙️ Senior Software Engineer — Decades of Experience

Verdict: Sound, but two technical landmines to defuse.

Landmine 1 — Vercel function timeout: Vercel's hobby plan has a 10-second timeout for serverless functions. Gemini AI calls routinely take 5–15 seconds for a full narrative response. You will hit this. Fix: implement streaming responses (both Gemini and Claude SDK support streaming) — stream tokens back to the client as they arrive. This also improves perceived performance dramatically.

Landmine 2 — Stateful assumptions in Express: The current app almost certainly has in-memory state (plan cache, maybe session data). Serverless functions are stateless — each invocation is a fresh process. Audit for any module-level state. The hash-based plan cache currently in SQLite needs to move fully into PostgreSQL. Don't cache in memory.

Migration path: better-sqlite3 → postgres (npm) or Drizzle ORM. Add user_id as a foreign key to every table. Not complex, but needs doing carefully with proper migrations — don't just ALTER TABLE in production.

Good news: The financial engine (amortisation, strategy, calculator) is pure JS with no DB coupling. It migrates for free.

🏗️ Senior Solutions Architect — Decades of Experience

Verdict: AI abstraction layer design is underspecified — define the interface now.

The "pluggable AI layer" is the right call but vague. You need a concrete interface before implementation or it'll be spaghetti:

// Server-side AI router — pseudocode
async function getAIProvider(userId) {
  const key = await getUserAnthropicKey(userId); // decrypt from DB
  if (key) return new ClaudeProvider(key);
  return new GeminiProvider(process.env.GEMINI_API_KEY);
}

BYOK key security: Where does your encryption key live? It must be a Vercel environment variable (AES-256), never in the database. The encrypted key goes in the DB; the decryption key stays in the server environment. This is non-negotiable for a financial app.

UK GDPR note: You're storing financial data. Supabase and Neon default to US regions. Both offer EU regions — use them. Vercel also has EU edge. Set this up from day one; migrating region later is painful.

Row-level security: Use Supabase RLS or application-level user_id filtering consistently. Don't mix the two — pick one pattern and enforce it everywhere. Application-level is simpler to start; RLS is more secure at scale.

🤖 Senior AI Software Engineer — Decades of Experience

Verdict: Gemini is a good choice, but your existing prompts need a rewrite.

The current app was built around Claude's specific capabilities and prompt style. Gemini Flash understands the same financial concepts but responds differently — it's more concise, less narrative. The existing prompts tuned for Claude's voice will produce noticeably different (often worse) output from Gemini without adjustment. Budget time for prompt engineering on the Gemini path.

Gemini free tier limits: 15 requests per minute, 1,500 requests per day, 1M tokens per day. For a financial planner with a handful of users this is more than enough. Add a simple per-user rate limit (e.g., 20 AI analyses per day) to protect the shared quota.

Streaming is essential: A non-streaming 8-second wait for an AI narrative on a phone feels broken. Streaming makes the same response feel instant. Both Gemini SDK and Anthropic SDK support streaming — implement it from day one, not as an afterthought.

Model selection: Gemini 2.0 Flash is the right default — faster and cheaper than Pro, more than capable for financial narrative. When users BYOK with Anthropic, default to claude-sonnet-4-6 — it's the best balance of quality and cost for this use case.

🧪 Senior QA Automation Engineer — Decades of Experience

Verdict: Testing strategy needs a rethink for this stack — don't inherit the same approach blindly.

AI must be mockable: Your AI layer abstraction is good for testing too. Define a MockAIProvider that returns deterministic responses. Every test that involves AI should use the mock — never call real Gemini/Claude in CI. This keeps tests fast, free, and reliable.

Database isolation: Create a separate Neon branch (Neon supports database branching, it's a killer feature) for the test environment. Your CI pipeline gets its own isolated database that's reset between test runs. No shared state pollution.

Auth in tests: Supabase Auth in E2E tests is painful — OAuth flows don't work headlessly. Use Supabase's test helpers to mint JWTs directly, bypassing the UI login flow. Your Playwright tests should authenticate via API, not via the Google login button.

Cold start testing: Vercel serverless cold starts will flake your E2E tests. Add explicit wait strategies and increase timeouts in your Playwright config for the CI environment. Consider a warm-up request before the test suite runs.

PWA testing: Playwright can test PWA installation on desktop Chrome. For real mobile device testing, BrowserStack has a free trial — use it at least once before shipping to your brother.

📋 Senior Product Manager — Decades of Experience

Verdict: The brother experience is underdesigned — fix onboarding before anything else.

iOS PWA reality check: Apple Safari doesn't show an "Add to Home Screen" banner automatically. Your brother needs to manually tap the Share button → "Add to Home Screen." This is not obvious. You need an in-app prompt that detects iOS and shows a visual guide ("Tap the share icon, then Add to Home Screen"). Otherwise half your users will just use it as a browser tab and the experience suffers.

Onboarding gap: The current app assumes you know what debt tranches, avalanche vs snowball, and amortisation mean. Your brother doesn't. Before he can use the app, he needs a 3-step setup wizard: add your income → add your debts → see your plan. No jargon. One thing at a time.

What happens when AI fails? Gemini quota exceeded, network error, provider down — what does your brother see? "Something went wrong" is not acceptable for a non-technical user. Design the fallback message now, not when it breaks in production.

The good news: The core product is genuinely useful and the UX (from what I can see in the codebase) is well-considered. The financial calculations are solid. The path to a real product is clear — don't over-engineer it. Ship to your brother, get real feedback, then iterate.
